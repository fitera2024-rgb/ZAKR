# Hierarchy Account Transfer (HAT)

Детерминированный сервис корректирующих переносов по выбранным счетам и дереву
организаций. Денежные расчёты выполняются через `Decimal`; направление проводки
определяется исключительно остатками: дебетуется аналитика с отрицательным остатком,
кредитуется аналитика с положительным остатком.

## Быстрый старт

```bash
python -m pip install -e '.[test]'
python -m hierarchy_account_transfer inspect --journal local_inputs/journal.xlsx \
  --hierarchy local_inputs/hierarchy.xlsx --template local_inputs/template.xlsx --out runs
python -m hierarchy_account_transfer analyze --inspection-id <id> \
  --root-org-code ROOT-001 --accounts 25,26 --scenario Факт \
  --date-from 2025-01-01 --date-to 2025-03-31 --rules config/rules.hat.yaml --out runs
python -m hierarchy_account_transfer export --run-id <id> --out runs
uvicorn hierarchy_account_transfer.api:app
```

## Пользовательский установочный архив

Готовый архив автоматически собирается GitHub Actions без добавления бинарных файлов
в Git. Откройте вкладку **Actions**, выберите последний успешный запуск
**Build HAT installer**, затем скачайте artifact `HAT-Installer-1.0.1`.

```bash
python scripts/build_installer.py
```

Команда создаёт `dist/HAT-Installer-1.0.1.zip` и файл контрольной суммы SHA256. В архив
входят приложение, интерфейс, пример правил и установщики для Windows/Linux/macOS, но
никогда не входят `local_inputs/`, `runs/` и бухгалтерские XLSX. В Windows достаточно
распаковать ZIP и запустить `Установить HAT.cmd`: Python и зависимости при необходимости
загружаются автоматически. После установки приложение запускается через
`Запустить HAT.cmd`.

После запуска откройте `http://127.0.0.1:8000`. Web-интерфейс проводит пользователя
через три этапа: локальная загрузка и проверка XLSX, выбор корня/сценария/периода/точных
счетов, затем просмотр статусов и блокировок, скачивание контрольного отчета и безопасный
экспорт. Кнопка выгрузки недоступна при глобальном блокере.

`inspect` копирует входы в локальное хранилище `runs/`, вычисляет SHA256 и возвращает
доступные корни, счета, периоды и сценарии. `analyze` всегда создаёт JSON-артефакты и
`run_control.xlsx`, даже если все кандидаты заблокированы. `export` повторно проверяет
инварианты и создаёт файлы только для `READY`.

## Статусы и ограничения

* `READY` — доказанная, безопасная и представимая проводка.
* `REVIEW` / `PROPOSED_PAIR` — требуется правило; не экспортируется.
* `BLOCKED_*` — конкретный инвариант не выполнен; не экспортируется.
* `NO_ACTION` — остаток уже закрыт; `ALREADY_APPLIED` — ID найден во входном журнале.

Выбор счетов точный, без автоматического включения субсчетов. Частичное закрытие,
fuzzy matching, перенос между корнями и ухудшающее направление запрещены. Cross-org
выгрузка требует подтверждённого capability адаптера. Реальные журналы следует хранить
только в `local_inputs/`; `local_inputs/` и `runs/` исключены из Git.
